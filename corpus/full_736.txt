一、实现方式
在
C2A（ChatGPT2API）
项目于 8 月 9 日更新之后，项目本身取消了账户自动注册功能。
因此，现在可以将账户自动注册这一部分交给
AAR（Any Auto Register）
来完成。
AAR 不仅支持 ChatGPT 等账户的自动注册，还可以配合：
自定义邮箱验证码服务
Turnstile 验证处理
手机号接码服务
AT / RT 获取
账号批量注册
从而完成整个自动注册流程。
项目地址：
Any Auto Register GitHub 项目
如果你之前已经按照我的教程部署过 ChatGPT2API，那么这套方案基本不需要改变原来的使用方式：
AAR 负责注册账户 → 导出账户 → 导入 ChatGPT2API → 使用多个账户轮换调用。
二、安装 AAR
这里我还是推荐大家使用
Docker
部署，安装过程比较简单，也方便后续升级。
直接执行下面的命令：
mkdir -p any-auto-register && cd any-auto-register
cat > docker-compose.yml <<'EOF'
services:
app:
image: ghcr.io/lxf746/any-auto-register:latest
ports:
- "8000:8000"   # Web UI
- "6080:6080"   # noVNC 可视化浏览器
- "8889:8889"   # Turnstile Solver
environment:
- DISPLAY=:99
# - APP_PASSWORD=changeme
volumes:
- ./data:/app/data
restart: unless-stopped
EOF
docker compose up -d
Docker 会自动拉取镜像并启动 AAR。
部署完成后，可以使用下面的地址访问 Web 管理界面：
http://localhost:8000
如果 AAR 部署在远程服务器上，则将
localhost
换成服务器 IP 或域名即可。

自定义邮箱和手机号接码是自动注册过程中比较关键的两个部分。

完成上面的配置之后，就可以开始自动注册了。

因此，
不要仅仅根据列表中的状态判断账户是否真正失效，最好实际调用测试一下。
五、设置自动注册参数
点击「自动注册」之后，会弹出注册方式选择界面。
点击“自动注册”，会弹出一个选择框，直接选择“使用系统邮箱注册”。
模式选择：可以选择“协议模式”或者“可视浏览器自动”。后者会更稳一点，但应该占用资源更多。
参数设置：注册数量和并发数都先设置为 1，进行测试。
开始注册：设置完成后往下滑，点击“开始自动注册”，就会进行自动注册。
你可以在弹出的框中查看日志。
如果你选择第三个可视浏览器中启动的话，可以在下面的链接中查看具体的操作。
http://localhost:6080/vnc.html
注册成功之后，账户会自动出现在 AAR 的账户列表中。
如果注册流程完整完成，并成功获取到 RT，那么导出的账户通常会同时包含：
AT（Access Token）
RT（Refresh Token）
相比只有 AT 的账户，这种账户在后续使用过程中通常更加方便，也不需要频繁重新获取 AT。
六、将账户导入 ChatGPT2API
这个项目的账号是可以自动导入到any2api中的。但如果你和我上一期教程一样，使用的是
ChatGPT2API
，那么需要手动进行一次账户迁移。
操作非常简单。
点击“导出”，选择“导出 JSON”，会下载一个 JSON 格式的文本。这个文件里面就是刚刚注册好的账户信息。
到 ChatGPT2API 项目的“账号管理”里面，选择“导入 CPA JSON 文件”，选择刚才的文件。
完成上述步骤后，就会自动进行账号的导入和同步。
这样，刚刚通过 AAR 注册的账户就可以直接用于 ChatGPT2API 了。
通过完整流程获取到 RT 后，ChatGPT2API 可以在需要的时候利用 RT 重新获取新的 AT。
只有 AT：使用时间相对较短，需要频繁更换账户。
AT + RT：后续可以自动刷新 AT，长期使用更加方便。
这也是为什么这次我更推荐大家通过 AAR 注册能够获取 RT 的账户。
